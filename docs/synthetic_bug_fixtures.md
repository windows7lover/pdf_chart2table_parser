# Synthetic bug fixtures — recovery-accuracy failure modes

Generated by `scripts/gen_fixtures.py` (added in this batch). Each fixture is a
matplotlib-rendered synthetic chart with exact ground truth (`.pdf` + `.eps` +
`.json`). Run `scripts/eval_extraction.py` to compare parser output to truth.

**Self-test:** feeds perfect ground truth back to eval — always PASS; this only
verifies the fixture schema is valid.

**Parser run:** `uv run pdf-chart2table parse tests/fixtures/<name>.pdf -o /tmp/out`
followed by `scripts/eval_extraction.py --pred /tmp/out/<name>/page1_chart1.json
--truth tests/fixtures/<name>.json`.

**Self-test result legend:** All single-panel fixtures PASS self-test (schema
valid). The "Parser result" column shows the real bug signal.

## Mode 6 — Decimal & exponent tick labels

Tick labels like 0.2, 0.10–0.30, ×10³, scientific notation x-axis.
Judge report: "miscalibrated" cases.

| Fixture | Description | Parser result | Fix module |
|---|---|---|---|
| `decimal_ticks_01range` | x, y in [0, 1] — tick labels 0.0…1.0 | PASS | `axes.py` |
| `decimal_ticks_tight` | x in [0.10, 0.30] — tight decimal tick range | PASS | `axes.py` |
| `exponent_ticks_1e3` | y in [0, 5000] — ticks formatted as ×10³ | PASS | `axes.py` |
| `exponent_ticks_large` | x in [1e6, 1e8] — ticks 0, 20M, 40M, 60M, 80M, 100M | **FAIL (open bug)** | `axes.py` |

**`exponent_ticks_large` is an open bug reproducer.** The parser reads x-axis
tick values as normalised [0, 1] instead of [0, 1e8]. Median error 10%, max 50%
of axis range. Fix: `axes.py` — improve parsing of large-magnitude scientific
notation tick labels (e.g. "20" with axis offset "×10⁶").

xfail in `test_axes.py`: `exponent_ticks_large-r0c0-x` (tick values spurious).

## Mode 7 — Missing series (dashed/dotted/many)

Dashed and dotted series are dropped or broken into extra spurious series.
Judge report: "missing-series" (4 cases feedback_r1) and dominant "extra-noise"
from dashed segment breakpoints parsed as separate series.

| Fixture | Description | Parser result | Fix module |
|---|---|---|---|
| `solid_dashed_same_color` | Same color, same marker: solid + dashed — via `Spec` (standard render) | **FAIL (open bug)** | `lines.py`, `marks.py` |
| `dashed_same_color` | Same color, same marker: solid + dashed — via custom render with explicit `linestyle="--"` | **FAIL (open bug)** | `lines.py`, `marks.py` |
| `dotted_3styles` | Solid + dashed + dotted, different colors/markers | **FAIL (open bug)** | `lines.py`, `marks.py` |
| `four_dashed_semilogy` | 4 dashed series on semilog-y (all `linestyle="--"`) | **FAIL (open bug)** | `lines.py`, `marks.py` |
| `four_series_semilogy` | 4 series semilog-y, all solid | PASS | regression guard |
| `six_series_linear` | 6 series linear, all solid | PASS | regression guard |
| `dotted_intermediates_3` | 3 series: solid/dashed/dotted via standard render | PASS | regression guard |

**Three open-bug reproducers.** Detailed failure signatures:

- **`solid_dashed_same_color`** (via standard `Spec`): 2 truth series, only 1
  extracted — the dashed series is dropped entirely (`pred=1`). Missing recall.
- **`dashed_same_color`** (via custom render with `linestyle="--"`): 2 pred
  series found, but solid series has 80 points instead of 40 — dashed segments
  merged into solid series (double-counts). Point values off by median 2.6%.
- **`dotted_3styles`**: 3 truth series, 5 predicted — dashed/dotted breakpoints
  create 2 extra phantom series. Extra-noise precision failure (precision=0.60).
- **`four_dashed_semilogy`**: 4 truth series, 8 predicted — each dashed series
  breaks into 2 segments. Precision=0.50.

Fix direction: `lines.py` — stitch evenly-spaced collinear short segments of the
same color into one series; do not emit each dashed segment as a separate series.
